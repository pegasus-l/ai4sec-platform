# 纠偏实施计划

## 0. 为什么要纠偏

当前 `ai4sec-platform` 已经有 FastAPI、SQLite、四域展示 API、旧数据导入器和最小 `PipelineRunner`，但实现路线存在偏差：

```text
当前实际实现：旧系统已处理结果 → importer → domain_items → API 展示
正确目标实现：数据源/旧 raw → RawArtifact → Normalize → Dedupe → Evidence/Review/Select → DomainItem → API 展示
```

当前实现可以保留为临时 demo 和字段摸底，但不能作为正式 pipeline 主线继续扩展。

---

## 1. 纠偏原则

1. 不删除当前可运行 demo，先把它降级为 `legacy_snapshot`。
2. 新增正式 pipeline 时从更靠近源头的数据读取，不再直接依赖 `selected_entries.json` 作为主输入。
3. 第一条正式 pipeline 先做 AI-for-Sec raw 六源，不同时重构华为和漏洞素材。
4. 前端以 v9 demo 的信息架构和数据契约为参考，但不直接照搬 HTML。
5. 每一步必须可运行、可测试、可回滚。
6. 仍然 shadow-only，不写生产路径。

---

## 2. 分阶段计划

### 阶段 A：标清当前实现边界

目标：避免后续误把旧处理结果导入器当正式 pipeline。

要做：

- 在文档和代码命名中明确当前导入器是 `legacy_snapshot`。
- README 说明当前展示数据来自旧处理结果，正式 pipeline 会从 raw 源重建。
- API 保持兼容，不破坏现有 demo。

验收：

- 文档说明清楚。
- 测试仍通过。

### 阶段 B：统计 v9 前端数据需求

目标：明确后端到底要为 v9 页面提供哪些数据。

要做：

- 阅读 `demo/index-v9.html` 和 `demo/FRONTEND_DATA_CONTRACT_DRAFT.md`。
- 在本文档补充 v9 页面数据需求表。
- 对比当前 API，列出缺口。

验收：

- 有明确的 API / 数据对象缺口表。

### 阶段 C：补 RawArtifact 和 NormalizedItem 基础表

目标：让平台能保存“源头数据”和“我们自己处理后的规范化条目”。

要做：

- 扩展 SQLite schema：`raw_artifacts`、`normalized_items`。
- 补 repository 方法。
- 不破坏已有表。

验收：

- 初始化数据库成功。
- 单元测试通过。

### 阶段 D：实现 AI-for-Sec raw 六源导入 step

目标：从旧 raw 文件读取源头数据，而不是直接读 `selected_entries.json`。

输入：

```text
/home/liuqi777/ai-for-sec-report/output/raw/arxiv_*.json
/home/liuqi777/ai-for-sec-report/output/raw/github_*.json
/home/liuqi777/ai-for-sec-report/output/raw/rss_new_candidates_*.json
/home/liuqi777/ai-for-sec-report/output/raw/x_new_candidates_*.json
/home/liuqi777/ai-for-sec-report/output/raw/asis_new_candidates_*.json
/home/liuqi777/ai-for-sec-report/output/raw/awesome_candidates_*.json
```

要做：

- 新增 `domains/news/adapters/ai_for_sec_raw.py`。
- 新增 `RawImportStep` 或专用 `ImportAiForSecRawStep`。
- 写入 `raw_artifacts` 和 artifact 文件。

验收：

- 可以指定日期导入 raw 六源。
- `raw_artifacts` 有记录。
- 不读取 `selected_entries.json` 作为主输入。

### 阶段 E：实现 NewsNormalizer 和 NewsDeduper

目标：把 raw 六源转成我们自己的 `normalized_items`。

要做：

- 新增 `domains/news/normalizers.py`。
- 新增 `domains/news/dedupe.py`。
- 支持 arxiv/github/rss/x/asis/awesome 的基本字段。
- 写入 `normalized_items`。

验收：

- pipeline 输出 normalized count。
- 有去重 key。
- 单测覆盖至少 arxiv/github 两类输入。

### 阶段 F：构造第一版 NewsItem / CapabilityCandidate

目标：先不调用模型，基于 normalized items 构造展示用 domain_items。

要做：

- 新增 `domains/news/builders.py` raw-based builder。
- 分数可以先用规则或空值，不伪装成模型评分。
- 能力候选只根据 repo/code_url/has_code 规则生成。

验收：

- `/api/news/today` 可展示 raw pipeline 结果。
- `/api/capabilities/today` 可展示 raw pipeline 派生能力候选。
- 明确标注来源为 `raw_pipeline`。

### 阶段 G：补 v9 API 缺口

目标：后端接口开始按 v9 数据契约收敛。

优先补：

```text
GET /api/news/items
GET /api/news/sources
GET /api/capabilities/items
GET /api/capabilities/repro-runs
GET /api/threats/targets
GET /api/threats/graph
GET /api/vulnerabilities/materials
GET /api/vulnerabilities/knowledge
GET /api/operations/quality-findings
GET /api/operations/queue-items
```

验收：

- v9 需要的数据有后端接口对应。
- 暂无真实数据的接口返回空数组和明确状态，不编造。

## 3. 当前优先执行顺序

先执行：

```text
A → B → C → D → E → F
```

暂不执行：

```text
真实联网采集
模型重跑
复现 runner
生产写入
华为/漏洞素材 raw pipeline 完整重构
```
