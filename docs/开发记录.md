## 2026-07-16 — 纠正“数据源获取”误解：当前只做本地原始数据导入

### 背景

用户指出当前阶段已经说过“先不做数据源获取”，但代码里出现了 `SourceConnector`、`raw_pipeline`、`arxiv/github/rss` 等名称，容易误解为已经在做联网采集。

### 纠偏结论

当前阶段不做联网数据源获取。平台只读取旧流程已经落盘的本地原始 JSON 文件，然后走新平台自己的处理链路：

```text
本地 raw JSON
→ raw_artifacts
→ normalized_items
→ dedupe / evidence
→ domain_items
→ model_calls / quality_audits / human_queue
→ API / 前端页面
```

### 已完成调整

- 在 `configs/app.yaml` 增加 `【已废弃】【已废弃】live_source_fetch_enabled: false`。
- 在 `Settings` 增加 `【已废弃】live_source_fetch_enabled` 配置项。
- `JsonFileConnector` 改为本地原始文件适配器语义：`source_type=local_raw_file_adapter`。
- `JsonFileConnector.fetch()` 遇到 HTTP/HTTPS 路径会直接返回 `【已废弃】live_source_fetch_disabled`，不会联网。
- `SourceRegistry.list()` 增加 `mode=【已废弃】local_raw_file_only`，API/调试时可以看到当前边界。
- 为三条已实现 pipeline 增加更准确的别名：
  - `news.ai_for_sec_local_raw_import`
  - 【已废弃】`【已废弃】threats.huawei_local_raw_import`
  - `vulnerabilities.material_local_raw_import`
- 保留旧 `*_raw_pipeline` 名称作为兼容入口，但 README 优先使用 `*_local_raw_import`。

## 下一轮人工校准

人工至少标注每条样本的 `association_label`：

- `direct_project`：漏洞描述、组件或版本能够证明与当前项目直接相关。
- `shared_dependency`：项目使用同一受影响依赖，关联合理，但不应描述成项目自身代码漏洞。
- `coordination_unassigned`：来自发布/安全协调仓，暂时无法分配到具体项目。
- `false_positive`：CVE 仅出现在模板、示例、引用链接或无关文本中。
- `duplicate`：同一组织/项目/CVE 的重复记录，应在入库前合并来源证据。
- `uncertain`：证据不足，保留原始记录并进入人工队列。

优先标注：所有 `release-management` 记录、全部扇出大于等于 4 的 CVE，以及随机抽取的 20 条普通项目记录。达到每类至少 20 条且双人一致率不低于 90% 后，才决定是否收紧 `_project_hints` / `_match_pool`；在此之前不改规则。
